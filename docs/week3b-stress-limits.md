# 第 3 周 B 段：压力测试 + 限额

## 1. 做了什么

```
scenario.json (13 个情景) ─► scenario
daily_price（全池）─► engine.stress.scenario_path ─► 每个历史情景的全池路径 ─► scenario_price_date（实际读到的价格日）
                                                    │
position / daily_price ─► jobs/stress.py ─► stress_result    历史：买入持有；假设：β 传导的因子冲击
                                                    │
risk_result / stress_result / 当日持仓与价格 ─► jobs/limits.py ─► limit_check   每条规则每天一行：ok / warn / breach / no_data
limit_rule.csv（5 条预置规则）─► limit_rule
```

- **engine（纯函数）**：
  - `engine/stress.py`：`proxy_returns`、`scenario_path`、`historical_stress`、`betas`、`hypothetical_shocks`、`hypothetical_stress`、`rank_scenarios`；
  - `limits/engine.py`：`evaluate`。
- **命令行**：`mrisk stress | limits --date D` 或 `--start S [--end E]`。
- **`mrisk daily`**：在归因之后依次跑压测和限额。限额对每条规则每天都写一行；breach 写 error 日志，warn 和 no_data 写 warning 日志。
- **门禁**：`jobs/gate.py` 的依赖登记新增"固定日期"（按情景记录）和"按情景区分"两种写法；上游结果失效时，下游的 `limit_check` 改写为 no_data。

## 3. 关键设计

### 3.1 历史情景：代理与停牌段对账

- **代理收益**：取同行业（股票池内）当天"有真实行情"的股票的等权平均；同行业少于 3 只时，用全池等权。"有真实行情"指当天和前一天都在交易。复牌日的收益含停牌期间的累积变动，不能当作代理的成分。
- **停牌段**：设停牌首日为 s、复牌日为 r。先在完整的日序列上处理：停牌日用代理收益，复牌日取残差 (P_r / P_{s−1}) / Π(1 + 代理) − 1，使整段累计等于真实涨跌；然后只截取 (基准日, 结束日] 内的那些天。
  - 复牌在结束日之后：残差落在窗口外，窗口内只有代理收益；
  - 停牌段跨过基准日：基准日之前的代理收益落在窗口外，不算进情景。
- **实现**：整个 (日期 × 股票) 矩阵一次算完。"每个复牌日对应哪个 s−1"用沿日期方向的 `maximum.accumulate` 求出；"段内代理收益的乘积"用累乘之比求出。没有按日期的循环。
- **未上市**：没有价格的日子和上市首日（没有前一天的价格）都用代理收益。
- **输出**：
  - 累计损益 = Σ 市值 × (Π(1 + r) − 1)；
  - 最大单日损失：沿买入持有路径取最大的单日亏损；
  - `pnl_proxy`：落在代理收益日上的那部分损益；
  - 代理市值，按"未上市""停牌"分开。
- **可加性**：压测损益在各层之间可以相加（行业之和 = 组合），测试断言了这一点，正好与 VaR 的不可加形成对照。
- **实际读到的价格日**由 engine 返回，范围从"跨过基准日的最早停牌段的 s−1"（或基准日本身）到结束日，不是手写的区间。job 读价格时，从"基准日往前 250 个交易日"和"库里第一个价格日"中较晚的那个开始；如果真有停牌段早于数据起点，engine 会报错，不会悄悄截断。

### 3.2 假设情景：β 条件期望

- 市场因子 = 全池（股票池内、窗口数据完整的股票）的等权收益；行业因子 = 该行业股票的等权收益。
- β_i = cov(r_i, f) / var(f)，E[r_i | f = s] = β_i · s，在零均值正态下与参数法口径一致。
- 行业内成员 β 的等权平均恰为 1，所以被冲击行业的等权指数恰好下跌 10%。手算和随机数据都测过。
- 因子情景每次只允许冲击一个因子；同时冲击多个因子需要多元条件期望，暂不支持，会直接报错。

### 3.3 限额评估（`limits/engine.py`）

- **判定**：breach = 检查值违反 `operator` 阈值；否则，违反 warn_ratio × 阈值时为 warn；否则为 ok。按 `<=`，值正好等于阈值不算违反；按 `<` 算违反。
- **比较是精确的浮点比较，不加容差。** 例如 0.9 × 0.07 与 0.063 相差一个最小精度单位。实际数据恰好落在线上的概率为零，测试改用二进制下能精确表示的边界来验证。
- **通配 scope**（`instrument:*`、`industry:*`）：检查值取成员中的最大值，detail 列出超过 warn 线的成员。指定了某只股票、但当天没持有时，集中度为 0。
- **no_data**：每条规则的输入单独判断。
  - 集中度只依赖当天的持仓和价格；
  - VaR 和 ES 依赖 `risk_result`，`risk_result` 又依赖整个窗口；
  - 所以窗口里某天价格出错时，集中度照常评估，VaR、ES 是 no_data。detail 里写明 `risk_result` 被门禁拦下的原因。

## 4. 怎么验证的

`uv run pytest`：共 201 个测试，全部通过（A 段收尾时 178 个，本段新增 23 个）。

- **停牌段对账三个手算用例**（被测股票 X 与三只同行业股票同属银行，代理收益 = 三只同行业股票的等权平均）：
  - **情景内复牌**：X 在 D2–D3 停牌，D4 复牌。残差 = (9.8 / 10.5) / (0.98 × 1.02) − 1 = −0.0662932，累计收益恰好等于 P6 / P1 − 1；
  - **停牌持续到结束日之后**：窗口内末三天是代理收益（−2%、+1%、+1%），累计 = 0.98 × 1.01 × 1.01 − 1。这部分损益全部记为代理贡献；
  - **基准日在停牌中**：停牌从 D1 开始，基准日为 D2。累计 = (P6 / P0) / (1.01 × 0.98) − 1 = 0.0188119，基准日之前的两天代理收益没有算进去；读到的价格日从 D0（即 s−1，早于基准日）开始。
- **其他引擎测试**：
  - 代理：同行业不足 3 只时退回全池；复牌日不作为代理成分；
  - 未上市股票用代理收益；
  - 停牌段早于数据起点时报错；
  - 买入持有的手算：组合 −66、最大单日损失 156，行业、个股逐项核对，各层相加一致；
  - β 手算：β_A = 18/26、β_B = 34/26，等权平均为 1，"银行 −10%" 恰好让行业指数跌 10%；
  - `raw` 冲击的优先级（个股 > 行业 > 市场），因子模式只允许一个因子。
- **限额**：
  - `<=` 和 `<` 的边界、warn 线；
  - 通配取最大值并列出超线成员；
  - 指定股票但当天未持有；
  - absolute 与 pct_of_mv 两种阈值；
  - 缺输入的规则写 no_data、其余规则照常评估；
  - inactive 规则跳过，未知指标报错。
- **端到端**（假数据源，情景放在 2025 年 5 月，SH600003 在 05-14 停牌）：
  - HIST_A 的组合损失 = Σ 市值 × (P_end / P_base − 1)，从库里独立复算；
  - HIST_B 的基准日落在停牌中，登记的价格日从 05-13 开始；
  - 行业 −10% 的结果与用库中收益独立算的 β 一致；
  - **固定日期依赖**：05-19 的价格被判失败后，只有 HIST_B 被拦下并删除（05-19 在它的读取范围内），HIST_A 和假设情景不受影响；依赖 HIST_B 的限额检查变为 no_data，detail 写明失效来源；重算后仍是 no_data，带门禁原因，不会缺行；
  - **限额**：每条规则每天一行；窗口内出现坏价格时，VaR 规则为 no_data，集中度照常评估（单只股票全部 breach）。
- **一个只在真实数据上暴露的 bug**：pandas 3 从库里读出的数组是只读的，engine 里一处原地运算 `s &= listed` 报错。单元测试的数据由字典构造、数组可写，所以没抓到。已改为生成新数组，端到端测试覆盖了这条路径。

**解读**：
- SPEC 原预置的 25% 会让每一天都 breach。
- 阈值落在 35%–42.5% 之间时，大量日子的状态取决于"代理部分算不算"。以 37.5% 为例：算上代理有 401 天 breach，不算代理一天都没有。
- 原因是这个组合有四成多的市值在 2015 年股灾期间停牌，或者当时还没上市（BJ920682）。

**拍板：阈值 45%，warn 90%（warn 线 40.5%），按含代理部分的口径评估。** 上表用的是 warn 80%；改为 90% 后，497 天的结果为 ok 459 天（3 段）、warn 38 天（2 段：2026-01-05 至 02-04 共 23 天，02-06 至 03-06 共 15 天）、breach 0 天（0 段）。

理由：
- **阈值不能否定策略本身。** 组合满仓做多 A 股，2015 情景损失在 36%–42% 之间，几乎是常数（497 天的极差只有 5.2 个百分点）。原定的 25% 相当于要求组合留约三分之一现金，这是在否定"满仓做多"这个策略，而不是在约束它的风险。
- **warn 90% 用来抓趋势。** 45% 的 breach 线在当前的持仓结构下不会被触发，真正起作用的是 40.5% 的 warn 线：它抓的是"组合慢慢变得更怕股灾"，例如持仓向 2015 年跌得更深的行业偏移。497 天里 warn 出现在 2026 年 1–3 月的两段，之后回落到 40.5% 以下（这两段的成因没有单独分解）。
- **"不含代理部分"那一列就是之前否掉的"停牌记 0"口径。** 把停牌和未上市股票的情景收益记为 0，等于假设四成多的市值在股灾中不亏钱。以 37.5% 的阈值为例，这个口径会藏掉 401 天的 breach。所以评估必须含代理部分；代理本身是否有偏，见 §5.5 a。

### 5.5 两个核对（只核对，不改代码）

**a. 代理有没有偏：2015 情景各停牌段的复牌日残差**

样本：停牌日落在情景窗口 (2015-06-12, 07-08] 内、或复牌日落在窗口内的停牌段，共 27 段、24 只股票（片仔癀、京东方A、网宿科技各两段）。BJ920682 当时未上市，不是停牌，不在样本里。残差与引擎的定义相同：(P_r / P_{s−1}) / Π_{s..r−1}(1 + 代理) − 1。它在完整日序列上算，所以复牌在窗口之后的段也有残差。

| 口径 | 段数 | 均值 | 中位数 | 标准差 | 为负的段数 | t 值 |
|---|---|---|---|---|---|---|
| 复牌日残差（引擎口径） | 27 | −1.17% | −0.66% | 7.99% | 15 | −0.76 |
| 　其中复牌在窗口内 | 5 | −1.81% | −0.66% | 7.02% | 3 | −0.58 |
| 　其中复牌在窗口之后 | 22 | −1.02% | −2.10% | 8.34% | 12 | −0.58 |
| 对账延到复牌后第一个非涨跌停日 | 27 | −0.02% | −0.73% | 10.73% | 15 | −0.01 |
| 参照：2015 年内复牌的全部停牌段 | 67 | +0.26% | −0.48% | 10.15% | 34 | 0.21 |

读法：
- **平均看，代理没有偏。** 均值 −1.17%、中位数 −0.66%，t = −0.76，与 0 没有显著差别。按"明显为负说明代理低估了损失"的判据，没有看到低估。
- **单段很不准。** 标准差 8%，最差 −16.2%（通富微电），最好 +20.3%（东方财富）。代理只在组合层面靠多只股票平均才可用，不能拿来看单只股票的情景损失。
- **涨跌停截断了复牌日残差。** 27 段里有 24 段在复牌日触及涨跌停，其中 21 段是涨停。大多是 07-07、07-08 "千股停牌"时停的牌，在 07-09 开始的反弹里复牌。复牌日收益被 ±10% 截住，追赶要几天才走完，所以复牌日残差不是干净的度量。把对账延到复牌后第一个非涨跌停日（代理也延到同一天），均值变为 −0.02%，结论不变。
- **局限**：只有 27 段。其中 22 段在窗口之后复牌，它们的残差覆盖整个停牌段，窗口内那几天的代理偏差无法单独分离出来。

**b. "银行 −10% 组合反赚 3.22%"**

最新窗口：2026-09-18 的 VaR 窗口，250 天，因子池 81 只股票，窗口数据都完整。

- 股票池里的银行股：**10 只**，全部在因子池内；组合当天持有其中 5 只，占市值 7.5%。
- 银行因子与全池因子的相关系数：**−0.075**。
- 银行因子对全池因子的 β：**−0.064**。
- 参照：全池因子含 10 只银行股，自相关会把相关系数往 0 拉。去掉银行后，71 只股票的等权因子与银行因子的相关系数为 −0.178。

银行因子与全池几乎不相关，所以"银行 −10%"对全市场的条件期望很小：全池因子对银行因子的 β 为 −0.089，条件期望是全池 **+0.89%**。组合赚 3.22%，来自行业结构，而不是来自"市场跟着涨"：

| 行业 | 持仓占比 | 该行业持仓的条件收益 | 对组合的贡献 |
|---|---|---|---|
| 电子 | 23.0% | +12.47% | +2.87% |
| 计算机 | 11.4% | +7.94% | +0.90% |
| 电力设备 | 17.3% | +2.82% | +0.49% |
| 有色金属 | 17.9% | +2.13% | +0.38% |
| 医药生物 | 8.2% | −0.71% | −0.06% |
| 非银金融 | 6.3% | −3.44% | −0.22% |
| 食品饮料 | 8.5% | −4.60% | −0.39% |
| 银行 | 7.5% | −10.00% | −0.75% |
| **组合** | 100% | | **+3.22%** |

- **主要是电子。** 电子行业因子与银行因子的相关系数为 −0.47；电子的日波动 2.9%，约为银行 1.0% 的 3 倍。β = 相关系数 × 波动比，所以电子行业因子对银行因子的 β 为 −1.35，单这一个行业就贡献 +2.87%。计算机、电力设备与银行的相关系数也是负的（−0.27、−0.25）；食品饮料、非银金融则是正的（0.43、0.24）。
- **低波动因子上的大冲击会被放大。** 银行因子的日波动只有 1.0%，−10% 相当于 10 个日标准差；同样的 −10% 打在全池因子上是 8.5 个标准差。单因子条件期望 β·s 对冲击是线性的，按 cov / var 缩放，低波动因子上的大冲击会把高波动股票的条件移动放得很大。
- 这仍然只是窗口内相关结构的结论，不是"银行跌、成长股一定涨"的预测。"银行 −10% 且全市场同时下跌"这类情景需要多因子条件期望，见 §6 第 5 条。

## 6. 已知局限 / 待确认

1. **2015 情景限额已定**：45%，warn 90%，含代理部分（§5.3）。阈值对代理口径非常敏感；代理平均无偏的核对见 §5.5 a。
2. **`limit_check` 的失效传递**：上游结果被删除时，依赖它的限额检查改写为 no_data，不删除。理由是"缺一行会被读成没问题"。已确认按这个原则处理。
3. **压测耗时 0.26 秒/天**：主要花在每天对全池重算 VaR 窗口和 β 上。每日增量只算一天，不受影响；全量重算 497 天需要 130 秒。
4. **因子池是股票池内的 81 只**，不是市场指数；β 反映的是相对股票池的联动。
5. **假设情景每次只能冲击一个因子**，`raw` 模式不受这个限制。多因子条件期望不需要联立回归，就是 E[r | f = s] = Σ_rf Σ_ff⁻¹ s：k 个因子解一个 k×k 方程。暂不实现，列为进阶；"银行 −10% 且全市场同时下跌"这类情景需要它。
6. **DQ 门禁按日期判断，不按股票**（沿用前几周）。全池代理也意味着：情景期内任一股票的价格失败，都会使该历史情景整体失效。
