# 第 2 周：计量引擎（市值、VaR ×2、ES、分层）

## 1. 做了什么

```
daily_price / position / instrument / dq_result
        │ （只从库里读，不拉行情）
        ▼
jobs/risk.py ── DQ 门禁：取每个日期最新一次 DQ，有 blocking 失败或没有 DQ 结果就不算
        │
        ▼  engine/（纯函数，不碰库、文件和网络）
  valuation.market_value      持仓 × 未复权收盘价 → 市值、权重、行业
  valuation.exposure_matrix   → 敞口矩阵 E (N×K)：组合 1 列 + 行业 1 列/个 + 个股 1 列/只
  returns.returns_window      后复权价 → 截至 as-of（含当天）的 250 个收益率 R (T×N)，停牌日置 0
  var.hs_var / hs_es          PnL = R @ E，沿日期轴一次求分位数和尾部均值
  var.param_var               σ = sqrt(diag(EᵀΣE))，VaR = z × σ
  risk.compute_risk           组装成长表：每个风险单元 × 每个置信度一行
        │
        ▼
risk_result（按 (trade_date, portfolio_id) 整块覆盖）+ 日志（停牌天数、ES 尾部为空的格子）
```

命令行：`mrisk risk --date D` 或 `mrisk risk --start S [--end E]`。有日期被 DQ 拦下或没有持仓时，退出码为 2。

## 2. 核心设计：一个敞口矩阵覆盖三层

E 的第 k 列表示一个风险单元：该单元内股票所在的格子填市值，其余为 0。于是：

- **历史模拟**：`PnL = R @ E`，形状 (T, K)，三层的历史损益一次算出；`np.quantile(..., axis=0)` 一次给出所有单元、两个置信度的 VaR。ES 用 (C, T, K) 的布尔掩码求尾部均值。
- **参数法**：`σ_k = sqrt((ΣE ⊙ E) 按列求和)`，即 `diag(EᵀΣE)`，然后 `VaR = z × σ`。
- 分层不需要第二条代码路径，也就没有任何"层与层相加"的逻辑。VaR 不可加是结果，不是约束。

整个引擎没有按日期的 Python 循环。只有 job 层对多个 as-of 日期逐日调用 `compute_risk`。

## 4. 关键取舍

- **`compute_risk` 输入长表，内部自己 pivot。** 调用方只需把库里的行原样传进来。窗口按"≤ as-of 的最后 251 个交易日"截取，as-of 之后的行会被忽略。持仓股在窗口内缺任何一天都会报错并列出股票代码。
- **停牌日显式置 0。** 真实库里 2,735 条停牌行的价格都沿用了前值，收益本来就是 0，显式置 0 只是守住 SPEC 口径。代价是：如果某条停牌行的价格变了，这个变动会丢失。复牌日的真实涨跌保留在复牌当天。
- **`es_tail_n` 放进 `compute_risk` 返回的表里作为一列**，与每一格对齐。job 写库前把它去掉，因为它不在 `risk_result` 里。
- **`param_sigma` 把 EᵀΣE 在舍入误差下的微小负值截到 0。** 数学上它是非负的；截断只影响整窗停牌、σ 精确为 0 的情形。
- **DQ 门禁取"每个日期最新一次 DQ 运行"。** 同一天可能有多次运行（backfill / daily / 手工重跑 dq），以最新的 `created_at` 为准。blocking 规则的清单读 `config.yaml` 的 `dq.blocking`，与 DQ 模块一致。
- **暂不支持的配置直接报错**：`holding_period_days ≠ 1`、`parametric_dist ≠ normal`。

## 5. 怎么验证的

`uv run pytest`：共 136 个测试（第 1 周 83 个 + 本周 53 个），全部通过，另有 1 个联网测试默认不跑。

- **手算，精确到小数点后 4 位（以元为单位），对应 SPEC §10 第 2 周验收**（`tests/test_risk.py`）：3 只股票（A、B 属银行，C 属电子）、T = 10。市值、三层五个单元的逐日 PnL、分位点位置 `(1−c)(T−1)`、线性插值、尾部均值、样本方差和 σ，全部在测试注释里逐步写出，覆盖 6 个单元 × 2 个置信度 × 4 个指标。
  - 例如组合层：PnL 最差两天是 −920 和 −230。VaR99 = 920 − 0.09 × 690 = 857.9；ES = 920；σ² = 1214000 / 9，参数法 VaR99 = 2.3263478740 × 367.2722272 = 854.4030。
- **ES 在 conf = 0.7 的手算**（`tests/test_var.py`）：分位点位置 2.7，VaR = 24.5，尾部 {−80, −50, −35}，ES = 55。同时断言 T = 10 时 ES95 = ES99（两者的尾部都只剩最差的一天）。
- **σ 两条路径相等**：`sqrt(diag(EᵀΣE))` 与 `std(R@E, ddof=1)` 逐列相等（rtol 1e-12）。
- **VaR 不可加**（`tests/test_risk.py`）：
  - 分散化：各股 VaR99 之和 973.1、各行业之和 964.1，都大于组合的 857.9；
  - 超可加：两只股票各在不同的一天暴跌 10%。T = 20、95% 时，单只 VaR 都是 50，组合 VaR 是 1000，大于 50 + 50。同时断言参数法满足次可加（σ 的三角不等式）。
  - 两个测试都**不断言**层与层相加相等。
- **参照实现**：用循环写的逐列、逐置信度参照实现，与向量化结果对比（rtol 1e-12 / 1e-10）。
- **性质**：ES ≥ VaR；VaR99 ≥ VaR95；持仓翻倍则各指标翻倍；log 收益下损失略大于 simple 收益。
- **报错路径**：缺价格、缺行业、历史不足、非正数量或价格、重复持仓、置信度越界、形状不匹配。
- **性能**：50 只 × 250 天，两个置信度、三层全部指标，`compute_risk` 单次约 70 ms（测试断言 < 1 秒）。
- **端到端**（`tests/test_jobs.py`，假数据源，lookback 20）：
  - 各层行数正确，组合市值与"数量 × 收盘价"一致；
  - **920 连续性**：窗口跨过 2025-05-06，BJ920682 只有一条序列，21 个价格没有缺口。它的个股 VaR 等于对"跨切换日的收益 × 市值"直接求分位数的结果；结果里没有任何 834682；
  - 重跑时覆盖旧行（被调出的股票消失，`run_id` 更新）；
  - DQ 门禁：较新的一次运行有 blocking 失败的日期判为 blocked；没有 DQ 结果的日期判为 no_dq；两者都不写库，并写 error 日志；
  - 历史不足时报错；
  - 整窗停牌的股票：停牌天数 = 20 写进 info 日志，ES 尾部为空的格子写进 warning，它的 VaR、ES、参数法 VaR 都是 0。

## 7. 已知局限 / 留给后续

1. **SPEC §6.2 的预置限额按现在的数据会频繁触发。** 组合 VaR99 超过市值 3% 的有 352 / 497 天，ES99 超过 4% 的有 422 / 497 天。第 3 周做限额时需要你决定阈值是否照原样，本周没有动。
2. **重跑会清掉 `pnl_actual`。** 重跑某天是整块覆盖，第 3 周回填的 `pnl_actual` 会被清成 NULL。第 3 周回填要做成可重复执行的步骤，或者在重跑后重新回填。
3. **被 DQ 拦下的日期不会清除旧的结果。** 某天先算过，之后 DQ 重跑判为 blocked，旧的 `risk_result` 行会保留（日志里有 error）。
4. **每日任务 `mrisk daily` 还没有接上风险计算**，目前需要单独运行 `mrisk risk`。
5. **SPEC §5.2 第 5 步仍写着 `z_0.99 = 2.326`**，实现用的是精确值（已拍板），SPEC 这一处没有同步。
